# Apps

每个 Bevy 程序都是一个 `App`，最简单的是：

```rust
use bevy::prelude::*;

fn main() {
    App::new().run();
}
```

之后执行 `cargo run` 就发现，什么都没发生。

因为我们还没告诉 `App` 要干什么，`App` 是一个我们程序的逻辑集合。

## App 由什么组成？

 `App` 到底存储了什么数据？从文档的目录来看，我们发现了三个关键词：`world`, `schedule` 以及 `runner` 。`world` 存储了所有的游戏的数据；`schedule` 持有操作这些数据的系统（包含操作的顺序），之后 `runner` 执行调度来控制执行的策略。具体的可以查看 Bevy 的文档。

总之，你会在更细的力度上操作这些 primitives：操控特殊的资源或者组件的数据并且在现有的schedule 上增加 system。

为了实现这些，我们通过 `builder pattern` 来在 `App` 上串联这些方法。最基础的工具有：

1. 初始化 `world` 里的供全局访问的只拷贝一次的资源。
2. 向 `schedule` 增加 systems，可以根据游戏逻辑读取和修改资源和实体组件
3. 导入 `App` 的其他块，通过 `plugins` 修改代码

下一部分开始会更细一点的介绍这些内容。

# ECS

Bevy 中所有的 app 逻辑都基于 ECS（Entity Component System）范例。ECS 是一种把你的程序分为：**Entities**, **Components**, **Systems** 的软件开发模式。

**Entities** 是指被赋予一些 **Components** 的唯一事物，之后它会被 **Systems** 处理。

例如，一个 Entity 可能会有 `Positions` `Velocity` 两个 Component，然后另外一个 Entity 可能会有 `Position` 和 `UI` Component。Systems 是执行在一系列的 Component 类型上的逻辑。你可能会有一个 `movement` 系统，负责运行所有拥有 `Position` 以及 `Velocity` 的组件的实体。

ECS 模式鼓励简洁、解耦的设计，强制你把数据和逻辑分开变为核心的 Component。它同时可以通过优化访存让你的代码更快、并行更简单。

## Bevy ECS

Bevy ECS 是 Bevy 的 ECS 模式实现。跟其他经常需要复杂的生命周期、traits、宏、builder pattern 的 Rust ECS 实现不同，Bevy ECS 使用 Rust 的类型描述所有概念。

- **Components**：实现 `Component` trait 的 Rust 结构体

```rust
#[derive(Component)]
struct Position {
    x: f32,
    y: f32,
}
```

- **Systems**：普通的 Rust 函数

```rust
fn print_position_system(query: Query<&Position>) {
    for position in &query {
        println!("position: {} {}", position.x, position.y);
    }
}
```

- **Entities**：包含一个唯一整数的简单类型

```rust
struct Entity(u64);
```

接下来看看他们的工作原理。

## 你的第一个 System

粘贴以下内容到 `main.rs`

```rust
fn hello_world() {
    println!("hello world!");
}
```

这是我们的第一个系统，之后你要向他添加：

```rust
fn main() {
    App::new().add_systems(Update, hello_world).run();
}
```

`add_systems` 函数增加了一个 system 给你的 App 的 `Update Schedule`，之后再讲这个。

现在运行程序，会看到打印了一次 `hello world`

> [!NOTE]
>
> [`add_systems`](https://docs.rs/bevy_app/latest/bevy_app/struct.App.html#method.add_systems) 向你的程序 Schedules 增加一个或者更多 system。
>
> [`Update`](https://docs.rs/bevy/latest/bevy/app/struct.Update.html) 每个渲染帧都执行的逻辑，通常包含 UI、输入控制、声音控制等等，游戏逻辑大部分应该被放在 `FixedUpdate` 中。
>
> [`FixedUpdate`](https://docs.rs/bevy/latest/bevy/prelude/struct.FixedUpdate.html) 包含大部分游戏逻辑，以固定的速率运行，通常包含：物理系统、AI、网络、游戏规则等。
>
> ps: 很多老游戏不区分渲染帧和游戏帧，就导致帧率越快游戏速度越快。
>
> [`Schedule`](https://docs.rs/bevy_ecs/latest/bevy_ecs/schedule/struct.Schedule.html) systems 的集合，并且包含所有运行时所需的元数据、执行器。

## 你的第一个 Component

向世界问好很棒，但如果想向一个人问好呢？在 ECS 中，通常你会把人建模为有一系列 Component 描述的 Entity。我们从一个简单的 Person 开始。

```rust
#[derive(Component)]
struct Person;
```

如果想让他有名字怎么办？

传统的设计中，我们会给 `Person` 一个 `name` 字段。但是其他的实体也可能会有名字。比如狗。所以把数据类型也分成小的 piece 有利于代码复用。所以：

```rust
#[derive(Component)]
struct Name(String);
```

我们之后把人增加到我们的 `World` 里，使用 'startup system'. 这也是一个普通的 System，但是只执行一次，且在所有其他 system 执行前执行。我们使用 `Commands` 来向我们的 `World` 生成一些 entites。

```rust
fn add_people(mut commands: Commands) {
    commands.spawn((Person, Name("Elaina Proctor".to_string())));
    commands.spawn((Person, Name("Renzo Hume".to_string())));
    commands.spawn((Person, Name("Zayna Nieves".to_string())));
}
```

之后注册 startup system：

```rust
fn main() {
    App::new()
        .add_systems(Startup, add_people)
        .add_systems(Update, hello_world)
        .run();
}
```

## 你的第一个 Query

执行后发现只有一个 hello world，我们的人物并没有什么反应。

我们需要让他们做出正确反应：

```rust
fn greet_people(query: Query<&Name, With<Person>>) {
    for name in &query {
        println!("hello {}!", name.0);
    }
}
```

我们传递的参数定义了这个 system 运行在什么数据上。在这里，`greet_people` 跑在所有具有 `Person` 和 `Name` 的 entities 上。

你可以把 `Query` 理解成：在所有具有 `Name` 和 `Person` Component 的 entities 上迭代。

现在给我们的 `App` 注册即可，你可以通过元组传递多个 system

```rust
fn main() {
    App::new()
        .add_systems(Startup, add_people)
        .add_systems(Update, (hello_world, greet_people))
        .run();
}
```

运行，即可看到成果。

注意，systems 之间是默认并行执行的。

## 你的第一个可变 Query

如果我们想改变 people 的名字（可能因为他们结婚了），举个例子，我们可以使用一个 mutable query：

```rust
fn update_people(mut query: Query<&mut Name, With<Person>>) {
    for mut name in &mut query {
        if name.0 == "Elaina Proctor" {
            name.0 = "Elaina Hume".to_string();
            break; // We don't need to change any other names.
        }
    }
}
```

需要让 `query` 可变，并且还需要给我们想更改的 Component 一个 `&mut`

```rust
fn main() {
    App::new()
        .add_systems(Startup, add_people)
        .add_systems(Update, (hello_world, (update_people, greet_people).chain()))
        .run();
}
```

我们对两个 systems 使用 `.chain()`，这是因为我们想让他们以确定的顺序执行：`update_people` 发生在 `greet_people` 之前。

但我们并没有把 `hello_world` 加进去，因为它无所谓。 

# Plugins

Bevy 的一条核心原则是模块化。所有 Bevy 引擎的功能都被实现为 plugins --- 修改 `App` 的代码集合。plugins 不仅包含内部功能，例如 renderer，而且游戏本身也作为 plugins 实现。这让开发者们更好的选择他们想要的功能。不需要 UI？那就不要注册 `UiPlugin`。想要构建一个 headless server 那就不要注册 `RenderPlugin`

这也意味着你可以自由的替换不需要的插件。此外，你可以制作自己的 `UiPlugin`，考虑把他上传给 Bevy，如果你觉得它会有用的话。

有一些作为第三方插件发布的内容，这些内容也很有用，防止你重复造轮子。如果想使用的话：

1. 寻找你需要的 Bevy 第三方 Plugins
2. 把它作为 `[dependencies]` 加入 `Cargo.toml`
3. import
4. 给你的 app 注册插件即可

然而，大多数开发者并不需要自定义插件，Bevy 提供了 `DefaultPlugins` 

## Bevy 的默认 Plugins

我们可以让 app 更有趣，增加 `DefaultPlugins`，它是一个 `PluginGroup`，包含了引擎的核心功能（也有一个 `MinimalPlugins`）

`add_plugins(DefaultPlugins)` 包含了大多数人们对引擎预期的功能，比如 2D/3D 渲染、资产加载、UI 系统、窗口化、以及输入控制。

```rust
fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_systems(Startup, add_people)
        .add_systems(Update, (hello_world, (update_people, greet_people).chain()))
        .run();
}
```

运行。

你会注意到：

- **一个窗口弹了出来**。这是因为我们现在有了 `WindowPlugin`，定义了窗口的接口（当然，并不知道实际如何组成窗口）以及 `WinitPlugin` （使用 [winit library](https://github.com/rust-windowing/winit)）通过 OS API 来创建窗口
- **你的控制台现在全是 "hello" 信息**：这是因为 `DefaultPlugins` 增加了一个事件循环。我们的 ECS 调度器现在每一帧都会执行循环。

## 创建你的第一个 Plugin

为了更好的代码组织，我们把 hello 的逻辑移入一个 plugin 中。我们只需要实现 `Plugin` 接口即可。

```rust
pub struct HelloPlugin;

impl Plugin for HelloPlugin {
    fn build(&self, app: &mut App) {
        // add things to your app here
    }
}
```

然后注册你的 Plugin：

```rust
fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_plugins(HelloPlugin)
        .add_systems(Startup, add_people)
        .add_systems(Update, (hello_world, (update_people, greet_people).chain()))
        .run();
}
```

注意，`add_plugins` 可以增加任意数量的 plugins（或者 plugins group），还是传元组即可。现在我们把剩余的 systems 移入 `HelloPlugin`，

```rust
impl Plugin for HelloPlugin {
    fn build(&self, app: &mut App) {
        // add things to your app here
        app.add_systems(Startup, add_people);
        app.add_systems(Update, (hello_world, (update_people, greet_people).chain()));
    }
}
```

`build()` 中的 app 变量和我们在 main 中的是一个类型。

# 资源

`Entity` 和 `Component` 数据类型可以很好的表示复杂、可查的数据组。但是大部分程序也需要全局唯一的某种数据。在 Bevy ECS 中，我们使用 `Resource` Trait 来表示全局唯一的数据。

以下是一些可以作为 `Resource` 的例子：

- Elapsed Time
- 资产集合（音效、材质、meshes）
- Renderer

## 使用 Resources 跟踪时间

我们让程序每两秒才输出一次 hello，使用 `Time` Resource 即可。通过 `DefaultPlugins` 已经加入到我们的程序了。

为了简单，我们移除 `hello_world` system。只需要适配 `greet_people`。

访问 Resource 的方法和访问 Component 的方法差不多，像这样：

```rust
fn greet_people(time: Res<Time>, query: Query<&Name, With<Person>>) {
    for name in &query {
        println!("hello {}!", name.0);
    }
}
```

`Res` 以及 `ResMut` 指针提供了读写资源的能力。

`Time` 的 `delta` 字段指出上一次更新后经过的时间。为了每 2s 执行一次我们的 system，我们必须跟踪一系列更新中经过的时间数量。为了简化这个过程，Bevy 提供了 `Timer` 类型，我们来通过 `Timer` 创造一个新的 Resource。

```rust
#[derive(Resource)]
struct GreetTimer(Timer);
```

在我们的系统中使用：

```rust
fn greet_people(time: Res<Time>, mut timer: ResMut<GreetTimer>, query: Query<&Name, With<Person>>) {
    // update our timer with the time elapsed since the last update
    // if that caused the timer to finish, we say hello to everyone
    if timer.0.tick(time.delta()).just_finished() {
        for name in &query {
            println!("hello {}!", name.0);
        }
    }
}
```

现在把 `GreetTimer` 加入 `HelloPlugin`，使用 `TimerMode::Repeating` 来让 timer 重复

```rust
impl Plugin for HelloPlugin {
    fn build(&self, app: &mut App) {
        app.insert_resource(GreetTimer(Timer::from_seconds(2.0, TimerMode::Repeating)));
        app.add_systems(Startup, add_people);
        app.add_systems(Update, (update_people, greet_people).chain());
    }
}
```

运行，现在就可以以一个正常的速率执行了
